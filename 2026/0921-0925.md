## Training Object Permanence in World Models

[在世界模型中训练客体永久性](https://arxiv.org/abs/2609.28654)

客体永久性（object permanence）与固体性是人类认知先验的标志性特征。近期研究表明，作为当前世界模型典型代表的视频生成模型已开始展现出推理能力，这使其成为构建类人物理智能的理想候选。那么，视频模型中是否已经涌现出客体永久性？如果没有，我们能否用一个受核心认知启发的数据集来训练它们？我们提出了 WROP（World Reasoning with Object Permanence），这是一个包含 150 个手工设计的、受认知科学启发的任务的数据基础设施，分为六个认知类别。我们构建了 Blender 生成器，在保持每个任务认知结构的同时，对速度、光照、相机角度及其他干扰参数进行随机化，每个任务生成 10,000+ 个样本。我们发布了一个 150 万样本的训练语料库和一套 300 题的测试。在该测试上，我们评估了 14 个视频模型：3 个参考到视频（reference-to-video）模型、7 个编辑模型和 4 个续写（continuation）模型，其中包括我们的 16B 世界模型 PWM-WROP。在一项盲测成对 Elo 研究中，PWM-WROP 在续写模型中排名第一、总体排名第三，仅次于两个参考到视频模型之间的统计并列。我们发布了数据、测试、模型答案、评分、权重，以及 PWM——我们在 AWS Trainium2 上的原生 PyTorch 训练栈。

## OmniEdu: Open Foundation Models for Learning and Teaching

[OmniEdu：面向学习与教学的开源基础模型](https://arxiv.org/abs/2609.23088)

教育基础模型必须能够解题、理解课程结构、诊断学习者的困难，并提供恰当的教学支持。现有的教育语言模型往往只侧重解题或辅导其中之一，其训练数据混合按来源或任务组织，而非按能力组织。我们提出 OmniEdu，一个面向 K-12 学习与教学的开源基础模型系列。其指令微调语料库整合了 100 多个教育资源与通用指令来源，围绕四种能力组织：学科能力、课程扎根、诊断推理，以及教学行动与支架。我们的流水线集成了确定性清洗、语义审计与改写、任务特定质量评分、Token 预算约束下的多样性选择，以及教学指令分配。最终产出 69,999 条样本、15.96M 个监督回复 Token，其中教育专用样本 60,951 条。我们微调了 4B、9B 和 27B 模型，并评估课程扎根、K-12 解题和教学辅导能力，同时考察通用能力。面向教育的微调在各模型规模上均持续提升三个教育基准组的表现。OmniEdu-27B 在 K12-Bench 上达到 63.12% EM 和 76.69% F1，在 MathFish 上达到 85.89%，在 EDUMATH 上达到 86.95%，在 MathTutorBench 的 Scaffold 设置下达到 78.74%。在受评模型中，它还在 LongTutor 上取得了最高的 Teaching 平均分，为 3.02。这些结果表明，经过精心策划、能力均衡的监督数据，对于将通用语言模型适配到涵盖解题、课程理解和教学支持的教育任务具有重要价值。

## Realtime-Venus: A full-duplex interaction system with asynchronous delegation

[Realtime-Venus：一种具备异步委派能力的全双工交互系统](https://arxiv.org/abs/2609.13814)

一个主动式全双工系统，采用音视频模型与音频模型分离的架构，实现持续感知、原生语音生成以及异步工具执行，支持实时对话。数字与物理环境中的自然交互需要持续感知和及时响应。语音对话依赖声学与语言线索，而视频交互还要求将对话建立在不断变化的视觉语境之上。我们提出 Realtime-Venus，一个主动式全双工交互系统，包含两个分别训练的 9B 模型：用于音视频交互的 Realtime-Venus-Omni，以及用于语音交互的 Realtime-Venus-Audio。每个模型都是一个完整的对话前端，通过一条共享的因果时间线整合用户输入、模型输出与委派事件，将持续感知、对话控制和原生语音生成融为一体。双循环运行时协调实时交互与后台推理和工具执行。前台交互持续进行，同时 Realtime-Venus-Harness 异步执行任务并返回结果，以融入正在进行的对话。两个模型遵循同一套后训练配方，结合了离线理解、主动式全双工轨迹以及委派工作流。在参与评估的在线模型中，Realtime-Venus-Omni 在八项视频基准中的六项取得最高分，包括 StreamingBench（70.2%）、OVO-Bench（64.7%）和 Daily-Omni（81.3%）。在八项音频理解与口语问答基准上，Realtime-Venus-Audio 在 MMAU（78.0%）、MMAU-Pro（63.2%）、Llama Questions（83.8%）和 Speech CMMLU（67.8%）上领先于所比较的模型，同时以 4.81 的成绩追平 VoiceBench AlpacaEval 的最佳分数。在 Full-Duplex-Bench v1.5 上，Realtime-Venus-Audio 对 75% 的用户打断作出响应，并在附和语（backchannels）、指向他人的语音和背景语音三种情境下分别达到 97%、88% 和 86% 的延续率，在三项延续指标上均超过 Gemini 3.1 Live 与 GPT-4o。

## RRSI: Regularized Recursive Self-Improvement of Agent Harnesses

[RRSI：Agent Harness 的正则化递归自我改进](https://arxiv.org/abs/2609.24972)

LLM Agent 的能力在很大程度上由其 harness 放大，即围绕冻结 backbone 模型的 prompt、控制流、工具、记忆与上下文管理。近期方法越来越多地通过迭代提出并选择 agent harness 的组件级编辑来自动化这一过程，实际上在 agent 系统层面建立了一种递归自我改进（Recursive Self-Improvement, RSI）机制。然而，这种递归演化可能通过记忆训练任务而过拟合，表现为分布内大幅提升，但在分布外基准上增益缩小甚至消失。我们提出 Agent Harness 的正则化递归自我改进（RRSI），将正则化原则引入 harness 自我改进，通过约束演化候选的提出与选择来实现。提出器采用随时间退火的预算，限制单个候选可捆绑的编辑数量，并基于演化历史鼓励探索未走过的轨迹。选择器配备 critic 与 pruner：critic 筛除针对特定基准的提案，pruner 则移除过小、代价过高或已不再有用的改动。这些约束共同倾向于可复用的 agent 机制，而非特定于基准的改动甚至噪声。在涵盖编码、agentic workspace 与工程设计任务的八个基准上，RRSI 在其演化所针对的划分上最高提升 14.1 分，在五个分布外基准上最高提升 4.7 分，同时产出的 harness 相比未正则化演化少用 30% 的 policy token。代码见 https://github.com/google-research/rrsi，项目主页为 https://regularized-rsi.com/。

## The Tasteful Agent: Measuring and Improving Taste in Long-Horizon Tasks

[有品味的 Agent：长时程任务中品味的度量与提升](https://arxiv.org/abs/2609.25804)

LLM Agent 越来越多地承担长时程（long-horizon）任务，而它们沿途所做的决策——例如该验证哪个假设、该基于哪个实现继续推进——决定了整个运行的结果。做好这些决策，正成为工程与研究类 Agent 的一项关键能力。我们将这种做出优质长时程决策的能力称为 Agent 的“品味”。现有基准虽能衡量 Agent 在长时程任务上的端到端成功率，却没有任何一个能衡量 Agent 的品味。为此，我们构建了 Taste-Bench：一个由 Agent 在工程与研究任务中产生的轨迹自动构建而成的品味问题基准。每个问题呈现一个决策分叉点（decision fork），即轨迹中同时存在多条可行方向、且其中一条通向更优结果的位置，被评估模型需在看不到分叉之后发生什么的情况下从中选择方向。我们从同一任务的多条并行尝试以及单条轨迹内部的绕行中自动挖掘这些分叉点，无需人工标注。我们在 Taste-Bench 上评估前沿模型，发现最佳模型仅答对 59.7% 的问题。我们进一步发现，对于那些决定性证据出现在轨迹较后位置的分叉点，所有模型的准确率都大幅下降，而且更大的推理预算并不能提升准确率。最后，我们证明品味是可以训练的：我们将已见结果的教师模型的判断蒸馏到学生模型中，学生模型在未见任务上做出更好的决策，并在留出的 SWE-bench Pro 任务上提升了端到端成功率。

## EvoOntology: A Self-Evolving Ontology Layer for Data Agents

[EvoOntology：面向数据智能体的自演化本体层](https://arxiv.org/abs/2609.15779)

数据智能体（Data Agent）旨在针对异构数据（包括表格、文件和数据库）执行自然语言指令。然而，数据智能体面临一个颇具挑战性的智能体—数据鸿沟（agent-data gap）：异构数据位于智能体外部，而智能体只能通过通用工具访问其中的部分信息（如列名和文件路径）。现有方法要么让智能体直接探索原始数据源，要么将人工构建的语义层注入提示词中。但这两种方式既难以扩展至大规模异构数据源，也无法适应不同智能体的行为。本文提出 EvoOntology，一种面向数据智能体的自演化本体层（self-evolving ontology layer）。EvoOntology 将本体封装为一个 MCP 服务器，包含模式层、内容层和工具层，使智能体能够在运行时主动查询并与本体交互。为此，我们引入一个构建器智能体（builder agent）用于自主构建本体，并设计了一个自演化循环，通过归因引导的类型化编辑（attribution-guided typed edits）持续优化本体，这些编辑仅在经过骨干模型条件化的配对评估（backbone-conditional paired evaluation）后才被接受。在三个广泛采用的数据智能体基准测试、四种 LLM 骨干模型上的实验表明，EvoOntology 持续优于强基线方法和现有语义层方法，有效弥合了智能体—数据鸿沟，并实现了与异构数据更高效的交互。代码：https://github.com/ruc-datalab/EvoOntology

## WorldCrafter: Consistent Video World Model with Implicit 3D-aware Memory

[WorldCrafter：具备隐式 3D 感知记忆的一致视频世界模型](https://arxiv.org/abs/2609.24984)

视频世界模型支持对动态环境进行交互式探索，但在长时程和跨视角条件下难以保持对先前观测的一致性。为此，我们提出 WorldCrafter，一种学习相机可查询的隐式 3D 感知记忆的视频世界模型。其核心思路是让请求的视角决定多视角证据如何被压缩进视频生成器有限的 Token 预算中。记忆编码器与姿态条件读取模块与视频生成器联合训练，在去噪之前将历史观测整合为一组固定的目标视角专属 Token，且无需显式的基于深度的对应关系。通过将该记忆与近期时序上下文以及少步蒸馏相结合，WorldCrafter 能够从单张输入图像或文本提示出发实现流式场景探索。在静态与动态场景上的实验表明，该方法在长时程一致性和相机控制精度上取得显著提升，同时在分钟级探索过程中保持了视觉质量。

## OmniVChat: Synthesizing, Benchmarking, and Training for Native Audio-Visual Dialogue

[OmniVChat：原生音视频对话的合成、基准构建与训练](https://arxiv.org/abs/2609.21465)

我们将 OmniVChat（Omni Video Chat）定义为用户与全模态模型之间的原生音视频对话任务。在 OmniVChat 中，全模态模型直接同步接收用户输入的音频与视频，并返回文本。用户的提问内嵌于音频和视频之中，无需单独的文字问题、外部字幕生成或语音识别。直接的音视频输入在保留感知线索的同时，降低了外部延迟与计算开销。然而，OmniVChat 的研究面临两方面限制：数据可得性与评估。人们使用自身设备时的录制数据十分稀缺。此外，优质回复往往需要兼顾用户所处环境、面部表情与周围物体，而这类回复可以有多种不同表达方式，使得关键词匹配难以可靠地评估回复质量。近期 Agent 系统与视频生成领域的进展使“以生成促理解”成为可行路径，即利用合成对话进行训练与评估。为此，我们提出 OmniVChat-Studio，一个用于合成单轮与多轮音视频对话的多 Agent 数据引擎。我们利用合成对话构建了 OmniVChat-Bench，一个在五类能力维度上评估全模态模型基础对话能力的评测基准。我们还提出 OmniVChat-RL，一种在 OmniVChat 中同时针对回复正确性、效率与风格的强化学习奖励设计。使用 OmniVChat-RL 在合成对话上训练 Qwen3-Omni-Instruct，可提升其在 OmniVChat-Bench 以及人工录制的 OmniVChat-Bench-Human 上的表现。这些增益验证了该奖励设计的有效性，并表明其在训练与评估中可迁移至真实世界对话。

## CodeMidas: Scaling Agentic Coding RL Environments from Code Itself

[CodeMidas：从代码本身扩展 Agentic 编程 RL 环境](https://arxiv.org/abs/2609.22068)

通过强化学习（RL）训练具备能力的编程 Agent，需要多样化任务以及可靠的验证器。开源代码库为这类任务提供了丰富的来源，但现有方法通常依赖 issue、commit 等开发过程产物，限制了可提取任务的范围。为更好地扩展 RL 环境，我们提出 CodeMidas——一条 agentic 流水线，仅以源代码作为任务特定输入，将现有代码库中已实现的功能转化为可执行的 RL 环境。CodeMidas 在环境构建的每个阶段都投入 agentic 计算：Agent 探索已实现的功能以形成行为规范，基于原始代码的执行构建测试，并通过执行检查和重复解 rollout 来验证与筛选候选任务。由此得到的数据集包含来自 3,185 个开源代码库的 5,545 个训练任务，覆盖 23 种编程语言和 15 个技术领域。使用 GRPO 在这些任务上训练 MiMo-V2.5，在五个多样化基准上均取得提升，涵盖问题修复（DeepSWE +11.7%）、整程序构建（ProgramBench +17%）以及终端操作（Terminal-Bench v2.1 +8.5%）。消融实验表明，增加高质量训练任务数量可提升性能。轨迹分析显示，经 RL 训练的 Agent 表现出更好的行为，例如增加对代码库的探索以及更多样化的自验证。这些结果确立了源代码作为构建 RL 环境可扩展基础的地位，能够提升编程 Agent 在多样化软件任务上的表现。

## GameHorizon Suite: Multi-Horizon Data and Evaluation in Gameplay

[GameHorizon Suite：游戏玩法中的多时间跨度数据与评估](https://arxiv.org/abs/2609.25001)

现代电子游戏为 AI 模型提供了一个可量化的试验场，它综合考察视觉理解、指令分解、目标规划以及在多个时间跨度（temporal horizon）上进行精确动作控制的能力。然而，现有数据集与基准要么覆盖的游戏范围狭窄，要么缺乏语言指令，要么依赖高方差的在线 rollout。为解决这些问题，我们提出了 GameHorizon——一套统一的数据与评估套件，用于衡量不同模型族在不同时间跨度上的游戏玩法能力。GameHorizon Suite 由三部分组成。第一，GameHorizon-Annotator 是一个可扩展、自动化的多时间跨度指令标注流水线。第二，基于该流水线，我们构建了 GameHorizon-Data，这是首个大规模 AAA 游戏玩法数据集，包含时间对齐的视频、玩家动作与多时间跨度指令，涵盖 21 款游戏、由 100 名人类专家玩家采集的 5,000 小时录像。第三，我们构建了 GameHorizon-Bench，支持可复现的离线测试与逐步在线测试。离线赛道使用数千道标准化问题实现可复现评估，这些问题被组织为三个主要任务及一系列诊断变体；在线赛道则检验离线分数是否反映真实游戏玩法能力，并将失败定位到长时程游戏过程中的具体步骤。基于 GameHorizon Suite，我们通过超过一百万次模型调用评估了 47 个模型，揭示了任务难度的明显层级以及模型能力之间的显著差异。我们的工作可为跨时间跨度、跨模型族的游戏玩法能力评估提供标准化标尺。我们将发布数据集、标注器与基准，以促进未来研究。

## Transferring the Intelligence of VLMs to Robotic Control

[将 VLM 的智能迁移至机器人控制](https://arxiv.org/abs/2609.22966)

人类能够无缝适应物理世界与数字世界，这表明尽管在具身形态、环境和任务上存在从数字到现实的鸿沟，人类智能本身却可以跨越这一鸿沟进行迁移。这自然引出一个根本性问题：视觉语言模型（VLM）的智能能否同样从数字世界泛化到物理世界，用于机器人控制？我们通过 RoboDawn 研究这一问题。RoboDawn 是一种符合人类直觉的接口，它通过一小组紧凑的离散平移、旋转和夹爪命令，将机器人控制暴露给具备 Agent 能力的 VLM。借助该接口，VLM 以闭环方式控制机器人：观察当前视觉状态、推理下一步动作、执行该动作，并根据执行后的状态调整后续决策。此外，我们提出一种上下文学习（ICL）方案，利用少量示范让 VLM 同时掌握接口使用方式和任务求解策略。在 RoboTwin 2.0 C2R 和 RoboDojo 上的实验表明，RoboDawn 无需针对特定任务进行机器人训练即可取得强劲性能。在零样本设置下，RoboDawn 优于多个基于基准专属机器人数据训练的强策略；而仅需一个上下文示范即可进一步提升性能，并达到 SOTA 结果。在 RoboTwin 2.0 C2R 上，成功率从零样本的 53.2% 提升至单样本的 73.6%，超过了强基线 π0.5（46.0%）。在 RoboDojo 上也观察到类似增益，成功率从零样本的 35.67% 提升至单样本的 47.17%。同一框架还可迁移至真实机器人，在 Franka 上完成积木入篮和积木堆叠任务。

## Grounded Skill Synthesis from Code at Scale for Agentic Intelligence

[从代码中大规模合成有依据的技能，赋能 Agent 智能](https://arxiv.org/abs/2609.05571)

Code2Skill 能够从源代码中自动抽取可验证的程序性技能，在 Agent 尚未积累交互经验之前就提升其表现。可复用技能为 Agent 提供可迁移的程序性知识，因此可扩展的技能获取对于让 Agent 突破既有经验边界至关重要。现有方法存在两点局限：基于轨迹的合成需要与特定环境交互，而从文档中衍生的技能可能缺乏可执行证据与验证。源代码提供了一条互补路径：它既不需要 Agent 具备先验经验，又能为抽象提供可执行证据作为依据。为此，作者提出 Code2Skill——一条全自动流水线，将选定的代码单元转化为锚定具体实现的记录，涵盖原子操作、复合工作流与重复出现的模式，并通过“遮蔽源本体重建 + 感知源信息比对”对每条记录进行验证。该方法应用于 19,769 个活跃维护的热门 GitHub 仓库，产出 CodeSkillBank：一个包含 1,006,822 条通过验收记录的有依据技能库，附带工作流、边界、来源与源证据元数据。在覆盖 9 种模型设置与 8 个基准的 72 项协议对齐评测中，检索 CodeSkillBank 技能进行增强的模型平均较匹配基线提升 11.7%，并在 57 项评测中胜出。在统一的下游接口下，Code2Skill 还在全部 7 个共同基准上优于由轨迹衍生的技能库，表明仓库衍生的技能能够在 Agent 积累足够交互经验之前就提供有用的程序性知识。由经过测试的 AI 生成代码合成的技能通过率为 93.50%，人类编写代码为 93.00%，这初步证明该流水线能够随 AI 生成软件规模的增长而扩展。总体而言，Code2Skill 将嵌入代码仓库中的程序性知识转化为有依据、可验证且可迁移的 Agent 技能。

## RULER: Instance-aware Rubric Rewards for SVG Generation

[RULER：面向 SVG 生成的实例感知评分规则奖励](https://arxiv.org/abs/2609.25270)

从自然语言指令生成可缩放矢量图形（SVG）代码是一项开放式任务，缺乏绝对的视觉真值，因此评估与策略优化都缺少可靠的信号。在自然图像上校准的标量指标（CLIP、Aesthetic）难以迁移到风格化的矢量内容，而将其复用为 RL 奖励会触发奖励作弊。我们通过基于评分规则（rubric）的打分同时解决这两个局限。首先，我们通过实验证实：以多维度评分规则提示视觉语言评判模型，其与人类判断的相关性在样本间和指令内都远优于标量指标。基于这一发现，我们提出 RULER（Instance-aware Rubric Rewards for Reinforcement Learning，面向强化学习的实例感知评分规则奖励），它将每条指令转换为一个包含语义、视觉与风格三个维度、共六个条目的实例感知评分规则；由评判 VLM 对渲染出的 rollout 逐条打分，加权后的满足度构成细粒度奖励，并通过组相对策略优化（Group Relative Policy Optimization）进行优化。由于评分规则仅由文本推导而来，RULER 既不需要成对的 SVG 真值，也不需要人类偏好标注。在 MMSVG-Illustration 与 MMSVG-Icon 上，RULER 将评分规则得分从 0.432/0.395 提升至 0.693/0.683，超越专门的 SVG 模型，并与体量大得多的 DeepSeek-V3 持平；消融实验表明，评分规则设计是开放式 SVG 生成中 RL 发挥作用的关键杠杆。项目主页见 https://hangyuran.github.io/RULER/ 。

## Your Transformer Can Hold Two Thoughts at Once: Evidence of Linear Superposition in LLMs

[你的 Transformer 能同时容纳两个想法：LLM 中线性叠加的证据](https://arxiv.org/abs/2609.29845)

尽管大语言模型（LLM）依赖高度非线性的组件，本工作表明它们仍展现出根本性的线性特征：当来自不同文本流的输入被线性组合时，模型输出的下一个 Token 分布是各单独分布的叠加。我们将此称为叠加线性假设（Superposition Linearity Hypothesis）。我们提供的证据表明，叠加是 Transformer 架构的固有属性，而非训练带来的涌现结果；事实上，我们观察到随着预训练推进，这种线性倾向会逐渐减弱。不过，我们证明通过轻量级微调可以大幅恢复线性，显著缩小预测的下一个 Token 分布与各单独分布均值之间的差异。最后，我们提出一种引导解码（guided decoding）流程，用于解耦叠加输出，从而在单次前向传播中同时生成两段连贯的续写。

## SpeakerMem-R1: Speaker-Centered Dual-Track Memory for Multi-Party Dialogue

[SpeakerMem-R1：面向多方对话的以说话者为中心的双轨记忆](https://arxiv.org/abs/2609.26780)

多方场景下的长期对话记忆不仅需要从长期对话中检索相关内容，还必须区分谁说了什么、每句话涉及谁、个体之间如何相互认知、哪些信息为群体所共享，以及状态如何随时间变化。近期针对多方对话基准的研究表明，现有的通用 LLM 记忆系统往往会丢失人物与群体关系，或难以整合分散在成员、群体和时间中的线索。这些问题共同揭示出两个核心瓶颈：多方对话中的消息归属（message attribution）与关系理解，以及从交错历史中重建状态。为解决这两方面问题，我们提出 SpeakerMem-R1：其双轨记忆存储带有说话者标注的逐字消息，以及按人物层面和群体层面视图组织的派生状态，并在查询时按实体、事件和时间融合两条轨道的证据。为在结构化记忆构建过程中减少归属与更新错误，同时支持本地部署，我们使用 SpeakerLevenshtein 和以说话者为条件的 GRPO 训练 Writer-R1。在 GroupMemBench、SocialMemBench 和 EverMemBench 上，SpeakerMem-R1 分别取得 47.9%、69.2% 和 61.9% 的二分类准确率。在 EverMind-AI 公开报告的 EverMemBench 排行榜上，我们达到 62.33%，为最新 SOTA 框架中报告的最佳结果。在全部 1,986 个 LoCoMo 问题上，我们也取得 70.85%，并将其用作两人长期对话的边界测试。在一项包含 305 个问题的受控评估中，RL 将 SFT Writer 的平均准确率从 57.38% 提升至 68.20%。我们同时报告二分类准确率和 token-F1，消融实验表明，在标准化评估接口下，逐字轨道与结构化轨道，以及人物层面与群体层面视图，均具有互补性。

## Grounded Action Model: 3D Grounding as a Foundation for Robotics

[具身动作模型：以 3D 定位作为机器人学的基础](https://arxiv.org/abs/2609.23863)

操作策略必须知道哪些物体重要以及它们位于何处，但当前机器人基础模型所依赖的预训练骨干网络——从视觉-语言-动作模型（VLA）中的语言，到世界-动作模型（WAM）中的视频生成——并不直接要求这种度量层面的定位能力，而是将其留给机器人演示数据隐式学习。为此，我们提出 Grounded Action Models（GAM），一种以 3D 定位为基础构建的机器人基础模型新范式。GAM 可以接受语言、点或框提示作为条件，这些提示首先被转换为所选物体的共享的以物体为中心的表示（object-centric representation）。该表示同时捕捉聚焦目标的视觉特征与物体的度量几何，并通过多流 Transformer 与机器人状态历史混合，用于预测动作块（action chunk）。GAM 既可自主运行，也可作为低层控制器，由高层规划器通过其多种输入模态进行控制，从而支持长时程与依赖记忆的操作任务。在 RoboTwin 2.0 上，GAM 在 50 项任务中取得 55.3% 的平均成功率（Spatial Forcing 为 52.0%），其中场景随机化条件下为 47.6%（Abot-M0 为 30.4%），而其动作策略仅在干净场景演示数据上训练。在 LIBERO-PRO 上，GAM 在 16 种扰动设置下取得 61% 的 SOTA 平均成功率（π_{0.5} 为 53%），在目标被重新放置或新指定时提升最为显著。在两台真实机器人上，GAM 在双臂 YAM 上面对视觉变化仍保持 17/20 的成功次数，而 π_{0.5} 为 4/20；其与 Molmo2 规划器组合后在 Franka 上执行长时程与依赖记忆的任务，取得 64.7% 的 ID 和 49.8% 的 OOD 步骤完成率。

## RecreationWorld: Scalable and Verifiable Environments for Hybrid Computer-Use Agents

[RecreationWorld：面向混合计算机使用智能体的可扩展可验证环境](https://arxiv.org/abs/2609.22000)

计算机使用智能体（Computer-Use Agent，CUA）此前沿两条独立路线发展：图形界面交互，以及通过代码和命令行进行软件开发。而真实的数字工作要求两者交织进行，而非端到端地顺序堆叠。我们研究混合型 CUA，它能自主决定何时探索界面、实现软件、运行并视觉验证其产物。我们提出 RecreationWorld，一个围绕“复刻”（recreation）构建的五平台框架：给定一个正在运行的参考实现，智能体必须自行发现其行为并构建出忠实实现，且不预设工作流程。RecreationWorld 在 Ubuntu、macOS、Windows、Android 和 Web 上提供可复现环境，并配备统一的测试框架，原生支持 GUI 控制与编码工具。运行中的参考实现充当隐藏行为测试的 oracle，提供基于执行的奖励。我们利用高质量开源应用扩展轨迹生成规模。在这些轨迹上训练的模型在五个分布外编码与混合计算机使用基准上均有提升，并更频繁地验证其渲染输出，表明这种迁移能力超出了复刻任务本身。为进行留出评估，我们提出 RecreationBench，包含跨领域、跨平台的 250 个多样化任务。基于参考实现的程序化与视觉断言覆盖多个交互深度上的动作条件结果；每个断言都在参考实现上验证并经人工审核，随后测试套件被冻结用于自动评分。GPT-6 Astra 以 58.1% 的总分领先，但仅在 2.8% 的任务上通过全部程序化测试。智能体复现静态界面结构比复现交互与计算结果更为可靠，而生成的应用程序相比参考实现仍更小、更单体化。我们发布该基准、环境与测试套件。

## Ovis-Embedding: Pushing the Frontiers of Universal Omni-Modal Embeddings

[Ovis-Embedding：推动通用全模态嵌入的前沿](https://arxiv.org/abs/2609.25165)

本报告介绍 Ovis-Embedding，一个 SOTA 级全模态嵌入模型系列，基于文本、图像、视频与音频的原生融合构建。该模型不采用独立模态塔拼接的方式，而是使用共享的多模态骨干网络，将不同模态编码到统一的表示空间中。具体而言，我们实现了三项关键进展：(1) 原生全模态初始化：采用预训练的 Qwen-omni 模型作为嵌入骨干，并通过低秩初始化的对比训练进行适配；(2) 以数据为中心的全模态训练：构建覆盖文本、图像、视频、音频及交错多模态数据的广泛高质量语料库。为提升数据效率，我们引入同源采样（homogeneous-source sampling），构建任务一致的批次，并提供信息量充足的批内负样本；(3) 面向嵌入的训练与推理优化：使用 focal loss 强化困难样本，并采用基于相似度的嵌入蒸馏（Embedding Distillation），从互补专家模型中迁移细粒度相似度结构。推理阶段，低秩特征分解可实现维度灵活、性能损失极小的紧凑嵌入。实证评估表明，Ovis-Embedding 系列在 MMEB-v3、MMEB-v2、MVEB、MAEB 和 RTEB 上均取得 SOTA 性能，验证了其在文本、图像、视频和音频模态上的有效性。这些结果凸显了统一全模态训练在克服模态碎片化、推进任意到任意检索通用嵌入模型方面的潜力。

## VideoGen-Agent: Reinforcing Video Generation Agents

[VideoGen-Agent：强化视频生成 Agent](https://arxiv.org/abs/2609.24997)

视频生成模型近期取得显著进展，已能生成高保真、时序连贯的视频。然而，这类模型往往难以满足需要专业知识、特定身份、物理一致性或有序事件的提示词。本文提出 VideoGen-Agent，一个通过多任务 Agent 强化学习（RL）训练的多模态 Agent，可调用外部工具完成视频生成。该 Agent 通过多轮交互协调增强、生成与验证工具，并依据提示词和中间观测来指导决策。我们在覆盖六类任务的类别均衡数据集上训练共享策略：先在教师模型生成的轨迹上进行监督微调，建立工具使用行为，再通过强化学习进一步优化。类别感知的混合奖励用于评估工具调用有效性、工具使用是否符合任务需求以及生成视频的质量。我们还提出 VABench，一个包含 600 条提示词的留出基准，覆盖流程性知识、单实体与多实体身份保持、物理一致性、场景构图以及多镜头时序结构。在 VABench 上，VideoGen-Agent 相比其基础文生视频生成器提升 19.1 分，从 56.5 提升至 75.6。在无需额外 Agent 训练的情况下，升级生成工具可将得分进一步提升至 86.1。在 84.3% 的对比中，人类评审更偏好升级后的配置，而非最强的独立基线。这些结果表明，跨视频生成任务学习工具使用是可行的，同时也说明经过训练的 Agent 能够受益于生成工具的后续进步。

## GAE: Learning a Geometry-Native Latent Space for 3D-Consistent World Generation

[GAE：学习面向 3D 一致世界生成的几何原生潜在空间](https://arxiv.org/abs/2609.24981)

本文提出一种紧凑的几何原生潜在空间（geometry-native latent space），作为感知与生成的共享基础。视觉生成器能够生成照片级真实的画面，却往往无法保持一致的 3D 场景。作者认为这不仅是建模问题，也是表示问题：生成器通常演化以表观为中心的潜在表示，而感知模型则在一个语义丰富、编码跨视角结构的空间中恢复几何。与将几何作为额外输出不同，本文把几何基础模型的特征重新参数化为一个紧凑的生成用潜在空间。这一转变通过几何原生自编码器（GAE）实现，其潜在表示可联合解码为表观、深度、相机与点图（point map）。基于该状态，标准的条件流（conditional flow）即可支持多种生成任务。在固定生成器与训练协议的受控对比中，以 GAE 替换原有潜在表示同时提升了视觉质量与独立测量的 3D 一致性：在 RealEstate10K 与 DL3DV 上 FVD 分别下降 12.7% 与 23.1%，在 RealEstate10K 上相机轨迹误差减半。这些结果表明，潜在空间对几何一致的生成至关重要，并可作为感知与生成之间的共享接口。

## Document Retrieval-Aware Chunking (D-RAC): Universal Retrieval-Aware Ingestion of Enterprise Documents via PDF Normalization and Multimodal Markdown Conversion

[文档检索感知分块（D-RAC）：通过 PDF 归一化与多模态 Markdown 转换实现企业文档的通用检索感知摄取](https://arxiv.org/abs/2609.24220)

面向企业知识库的检索增强生成（RAG）系统必须摄取异构文档格式——PDF、Word 文档、演示文稿和扫描件——其内容被锁定在复杂的视觉版面、多栏页面和密集表格之中。基于规则的抽取与 OCR 会破坏阅读顺序、将表格扁平化并丢失标题层级，而基于抽取文本的全 Agent 式分块则带来高昂的 Token 成本和幻觉风险。我们提出文档检索感知分块（D-RAC），将我们的 Web 检索感知分块（W-RAC）框架扩展到任意文档格式。D-RAC 首先将任意输入文档归一化为 PDF，利用几乎每种格式都存在忠实且确定性的 PDF 渲染这一事实。随后，单次多模态 LLM 处理将渲染页面转换为面向检索优化的 Markdown——把表格改写为自包含的叙述性语句，并保留标题层级——之后的分块流程与 W-RAC 完全一致：确定性解析为可被 ID 寻址的单元，再基于标识符而非文本进行轻量级 LLM 分块规划。分块过程中从不重新生成源文本，从而保留 W-RAC 在成本、确定性和可观测性方面的优势，同时让所有可渲染格式都成为一等输入。在涵盖五个企业领域的 RAG-Multi-Corpus 基准的 236 篇文档、795 页 PDF 子集上，D-RAC 在 72 分钟内零错误地完成整个语料的转换与分块，产出 1,748 个可直接用于检索的块。与使用前沿 LLM 的 Agent 式分块相比，D-RAC 将分块阶段的输出 Token 减少 95.7%，分块成本降低 77.8%（按 GPT-4.1 定价）至 85.6%（按 Gemini 2.5 Pro 定价），分块时间缩短 75%。D-RAC 可线性扩展至 500 页以上的文档。

## The Past Frames the Future: Memory for Autoregressive Video Generation

[过去帧定未来：自回归视频生成的记忆机制](https://arxiv.org/abs/2609.28466)

生成模型的进步提升了视频保真度，使长时程生成、交互式世界建模与持续演化的视觉环境成为可能。自回归（AR）视频生成通过因果式推演（causal rollout）延展视觉序列。然而，一个根本性瓶颈随之显现：随着生成序列不断扩展，实际模型必须在严格受限的上下文窗口、存储与计算预算下运行。因此，关键历史信息——如实体身份、动态状态以及干预引发的因果变化——往往在其相关性消退之前就早已离开活跃上下文。克服这一限制并维持时间持续性，本质上是一个记忆问题。本文对 AR 视频生成中的记忆机制进行了系统而全面的综述。我们将记忆在操作层面定义为：跨外层 AR 步骤持久保留的历史信息，即使其原始证据已不再可局部访问，仍能影响后续生成。基于这一统一框架，我们从五个互补视角组织相关文献：(I) 形式，即历史的表征载体；(II) 功能，即需要保留的具体语义与物理信息；(III) 操作，即记忆的写入、读取、更新、管理与整合生命周期；(IV) 学习，即闭环推演下记忆行为的优化；(V) 评估，即诊断真实记忆能力的范式。最后，我们综合梳理了开放挑战，包括可组合且资源感知的记忆架构、可信状态更新、自推演学习以及标准化评估。通过连接表征、机制与学习范式，本文为构建可靠、以记忆为条件的视频生成系统奠定了结构化基础。

## Spatial-Interactor: Learning Spatial Reasoning through Interaction with the Observable Physical World

[Spatial-Interactor：通过与可观测物理世界交互学习空间推理](https://arxiv.org/abs/2609.23038)

空间推理是视觉语言模型（VLM）理解物理世界并采取行动的关键能力。在动态环境中进行推理，要求 VLM 感知由物体运动和视角变化引起的局部状态转移，并在长轨迹上对其进行整合，以维持不断更新的空间状态；然而现有 VLM 在这两方面能力上均存在局限。当前的空间训练主要聚焦于关于物体属性和空间关系的静态问答，对状态转移的直接监督有限；相比之下，交互轨迹天然地将前序观测、动作与后续观测连接起来，为局部状态转移提供了直接监督，而完整轨迹则揭示了连续转移之间的依赖关系。为此，我们提出 Spatial-Interactor，一个通过交互训练 VLM 建模物理世界状态转移的框架，并将这一学习过程组织为三级课程：L1 被动式世界状态转移、L2 主动式自身状态转移、L3 长时程交互轨迹。相应地，我们基于模拟与真实交互轨迹构建了 Spatial Interaction 学习数据集（LSI-108K），其任务与各层级目标对齐。我们的两阶段训练策略先对 L1 和 L2 采用监督微调（SFT）以建模局部转移，随后使用同策略蒸馏（OPD）进行特权自蒸馏：由获得片段级转移描述的教师分支监督学生的同策略 CoT，帮助学生学会在 L3 长轨迹上整合连续转移。在多个 VLM 和空间基准上的实验表明，该方法在局部转移建模和长时程整合方面均取得一致提升。

## Paint-Anything: Unified Any-Color Control for Image Generation and Editing

[Paint-Anything：面向图像生成与编辑的统一任意颜色控制](https://arxiv.org/abs/2609.20816)

专业设计需要任意颜色控制：即能够用任意 24 位十六进制值指定物体的目标颜色，用于图像生成与编辑。此前工作已探索过颜色生成、编辑与上色，但往往依赖专用的颜色表示或专门的推理流程。大语言模型的进展提供了一个更简单的起点：即使是紧凑模型也能将十六进制值与颜色语义关联起来。我们提出 Paint-Anything，通过物体级颜色监督，学习一个用于生成与编辑的共享十六进制提示接口。我们开发了一条数据流水线，通过物体定位、感知颜色标注和编辑配对合成，从真实图像构建出 Paint-500K。由于阴影使得真实图像的标注只能近似颜色，我们用纯色锚点补充这一监督，其像素与配对的十六进制值完全一致。这些锚点仅在高噪声时间步使用，低噪声训练则交给自然图像。我们进一步提出任意颜色基准（Any Color Benchmark，ACBench），包含 ACBench-T2I 与 ACBench-Edit，用于衡量两项任务中的物体级十六进制颜色保真度。在 FLUX.2-4B 上，Paint-Anything 相比基础模型将 ACBench-T2I 和 ACBench-Edit 分数分别提升 85.3% 和 28.3%，消融实验也支持该训练方案。在对比方法中，它还取得了最高的平均 CompColor 分数。

## HappyWorld-Bench

[HappyWorld-Bench 基准测试](https://arxiv.org/abs/2609.24308)

评估世界模型需要同时衡量其生成世界的质量，以及其在探索、交互和修改下的一致性与响应能力。我们提出 HappyWorld-Bench，一个全面基准，用于评估生成世界在 Agent 与之交互时是否仍保持可靠。我们的设计基于六项世界观能力（W1-W6）的分层能力框架，涵盖从生成式构建到统一世界建模，并实例化为三个独立评估轨道：视频世界模型、空间世界模型和具身世界模型。HappyWorld-Bench 包含 1,138 个视频提示词、300 个空间场景和 254 个具身测试用例。在全部三个轨道中，我们构建并运行 HappyWorld-Arena，用于组织人类 A/B 对比并得出模型级 Elo 评分，以补充新设计的、可捕捉行为正确性的自动化指标。我们在这一统一框架下评估了 14 个视频世界模型、9 个空间系统和 8 个具身候选模型。结果揭示了三个轨道中仍存在的可靠性差距：视频模型在扩展推演与回访时一致性下降，空间模型最多达到 70.14% 的放置准确率和 73.33% 的编辑执行率，具身模型则难以在多步动作中保持状态，也难以对改变后的动作条件和物理规则作出精确响应。这些发现凸显出，评估世界模型不仅应关注视觉质量，还应关注状态一致性及其对动作和干预响应的正确性。

## StableVQ: Practical Guidelines for Stable Vector-Quantized Tokenizer Training

[StableVQ：稳定向量量化分词器训练的实用指南](https://arxiv.org/abs/2609.26774)

向量量化（Vector Quantization, VQ）是支撑现代自回归与掩码图像生成模型的离散视觉分词器的基础。尽管近期提出的共享投影码本（shared-projection codebook）方法大幅提升了码本利用率，训练稳定性仍是一个关键却未被充分探索的挑战。我们认为，其根源在于 Encoder–Decoder 与 Codebook 训练的耦合：由于任何一个模块都无法在孤立状态下可靠地履行自身职责，整个系统只有在两个子系统恰好协同工作时才能正常运转——而这一条件十分脆弱，恰好在训练压力最大时失效。为此我们提出 StableVQ，重新审视各模块应有的学习目标，并解决让每个模块独立履行自身职责时所产生的问题。具体而言：(1) Dynamic STE 修正了 Encoder 学习目标中的不稳定问题，使其即便在码本利用率较低时，也能在离散正则化下稳健地优化重建空间。(2) Region VQ Loss 重新构想 Codebook 的学习目标，使其能够独立保证对 Encoder 输出分布的完整追踪，而无需依赖 Encoder 的震荡来驱动激活。(3) Decoupled Schedule 认识到 Encoder–Decoder 与 Codebook 的不同职责要求不同的优化动态，因此为二者分别分配独立的学习率调度，以确保系统层面的稳健行为。StableVQ 构建在共享投影码本之上，轻量且不引入任何可学习参数。在 ImageNet 上的实验表明，在多种码本规模与初始化设置下，训练稳定性、码本利用率与重建质量均获得一致性提升。

## All-in-One Multilingual Scene Text Recognition with Script-aware Mixture-of-Experts

[基于文字系统感知混合专家的一体化多语言场景文本识别](https://arxiv.org/abs/2609.24058)

多语言场景文本识别（STR）仍面临挑战，原因在于大多数语言的训练数据稀缺，且难以在单一模型中服务多种文字系统。现有方案要么为每种语言部署一个识别器，导致成本膨胀并引入误差累积；要么依赖大规模视觉语言模型（VLM），代价高昂且在许多文字系统上仍不够准确。在本工作中，我们追求一个一体化的多语言识别器：比逐语言专家方案更简单，比 VLM 更轻量，且比两者都更准确。首先，我们构建了 TextMuSS-10M，一个覆盖 10 种文字系统、229 种语言的大规模合成场景文本数据集，在真实数据不可得之处提供均衡且充分的监督。其次，我们提出 ScriptMoE，一种文字系统感知的混合专家（MoE）架构。它共享单一视觉编码器，并以稀疏 MoE 模块替换稠密解码器：由图像级路由器将每张图像分派至 top-2 的文字系统对齐专家，另设一个共享专家吸收跨文字系统知识。在我们构建的 TextMuSS-Bench（10 种文字系统、10,899 张图像）上的大量实验表明，ScriptMoE 取得了 82.06% 的最高准确率，比最强的 STR 基线高出 1.31%。在 CC-OCR 端到端多语言任务上，仅将 PP-OCRv5 中的识别器替换为 ScriptMoE，即可将 F1 分数从 65.71% 提升至 80.89%，以极小的参数量略微超越最佳 VLM（80.73%）。

## onPanda: Efficient Annotation of On-Policy Alignment Data for LLMs and Agents via Token-Level Correction

[onPanda：通过 Token 级修正高效标注 LLM 与 Agent 的在线策略对齐数据](https://arxiv.org/abs/2609.24983)

我们提出 onPanda，一个用于高效标注 LLM 对齐数据与 Agent 轨迹的交互式工具。onPanda 以 Token 级修正（token-level correction）为核心交互方式：标注者在阅读模型回复时，定位第一个不合适的 Token，然后从模型的候选 Token 中选取替代项，或通过自由编辑直接输入正确文本。随后系统会截断该位置之后的所有内容，并从修正后的前缀继续生成，如此循环执行“定位—修正—继续”流程，直到获得满意的回复。该机制让标注者能够以低成本精确引导模型输出：一项小规模对照研究表明，相比人工后期编辑，onPanda 将标注时间中位数降低了 52%。由于最终回复中的绝大多数 Token 由模型自身生成，所得数据在很大程度上保留了模型的采样分布，非常适合用于构建在线策略 SFT 数据与偏好数据。此外，标注过程中记录的 Token 级修正提供了位置精确的细粒度监督信号，并天然形成正负样本对。onPanda 还可连接外部工具与运行框架（harness），从而在真实环境中进行交互式轨迹标注。我们还发布了使用 onPanda 标注的数据集 Panda-CVL，以及一个 Token 级修正基准。

## Just-in-Time Memory: Learning to Curate Task-Adaptive Memory for LLM Agents

[即时记忆：为 LLM Agent 学习策展任务自适应记忆](https://arxiv.org/abs/2609.27334)

Agentic 记忆系统通过复用过往经验来提升未来表现，但现有设计大多在写入时（write time）进行记忆策展：任务一旦完成，其轨迹便被蒸馏为固定产物，如反思、工作流、技能或推理策略，之后依靠相似度检索。这迫使系统在尚不知未来查询的情况下就决定什么值得记忆，不可逆地丢弃信息，并生成一个与查询无关、却要服务于众多潜在下游任务的摘要。学习这样的写入时策展器也很困难，因为某个存储决策的价值可能要到相关查询出现时才显现，甚至可能相隔许多任务，从而形成长时程的信用分配问题。我们转而保留原始轨迹，将策展推迟到读取时（read time），此时当前任务已知。给定检索到的轨迹与新任务，记忆策展器会合成一个紧凑、任务自适应的载荷，针对即时需求定制。由于该载荷在同一任务上被消费，策展器可以直接从即时任务成功中训练，避免延迟的效用信号，也无需人为地将相关任务分组。在 ALFWorld、WebShop 和 τ^2-bench 上，我们的即时记忆（JitMem）一致优于无记忆 Agent 以及启发式和习得的写入时记忆方法，相较最强基线分别提升 16.2、16.3 和 3.9 个绝对成功率百分点。值得注意的是，即使未经训练的策展器也已能与这些基线相竞争甚至超越，表明任务自适应的读取时策展本身就是主要增益来源；对策展器进行训练则进一步叠加提升。

## One to More, More to One: Category-Aware Iterative Expert Training for Software Engineering Agents

[从一到多，从多到一：面向软件工程 Agent 的类别感知迭代专家训练](https://arxiv.org/abs/2609.23377)

仓库级软件工程（SWE）包含异构任务类别，在混合式智能体强化学习下，各类别的进展可能不均衡：某些类别取得提升的同时，另一些类别却出现回退，而聚合后的解决率掩盖了这些变化。受这种类别跷跷板现象启发，我们提出了一个类别感知的专家训练与策略集成框架。可执行任务构建流程与 SWE Labeler——一个基于证据的多轴标注系统——共同组织训练池。初始的类别专属 RL 提升了平均训练成功率，但实例级进展仍不均衡，这促使我们显式地整合成功行为并采用策略自适应任务选择。同源类别专家交替进行长时程 Agentic-miniRL 与 Refresh-Repair-Expand（RRE）：更新后的策略刷新实例掌握情况，复用自身已验证的成功轨迹进行 Repair SFT，并重新选择任务用于后续 RL。标签路由的多教师同策略蒸馏（MOPD）将各专家整合为一个可部署的学生模型，并通过 ReLU 门控奖励外推，仅保留各教师相对于参考模型的改进方向。专家训练与策略集成无需外部模型提供解题轨迹或动作目标。我们通过聚合解决率与各类别解决率、相较各联合 RL 基线的最小类别提升，以及专家增益恢复情况，评估了 Pooled RL 与 Balanced RL、专家开发以及单模型集成。最终 MOPD 策略在 Pro-618 上取得 58.04% 的平均解决率，在 SWE-bench Multilingual 上取得 59.00%，分别较基础模型提升 5.39 和 2.78 个百分点。

## Bellman Policy Optimization

[贝尔曼策略优化](https://arxiv.org/abs/2609.15987)

带可验证奖励的强化学习（RLVR）提升了大型语言模型（LLM）的推理能力。我们提出贝尔曼策略优化（BPO），这是一种从策略镜像下降（PMD）推导出的无 Critic 方法。对于带终端奖励的自回归生成，BPO 利用贝尔曼方程将 PMD 重新表述为轨迹级目标，从而避免估计中间状态的状态价值。我们证明该重构目标与原 PMD 目标具有相同的唯一最优解。我们通过近似该目标推导出实用的 BPO 损失，其失配修正权重是互补 Token 概率的平滑比值。在数学推理基准上的实验验证了 BPO 的有效性。

## WanPE: Towards Cinematic Prompt Enhancement for Modern Text-to-Video Generation

[WanPE：面向现代文生视频的电影级提示词增强](https://arxiv.org/abs/2609.30221)

视频生成从文本空间起步——先撰写电影脚本，再落地为像素。随着当代视频生成器扩展到 30 秒并能忠实遵循复杂条件，文本提示词在很大程度上主导了整个制作过程，规划动作、镜头轨迹、光照与声音如何在多镜头序列中展开。本文提出 WanPE，一个拥有 397B 参数、在 105 万条真实世界视频上训练的提示词增强模型，旨在掌握导演级的电影化规划能力。WanPE 通过基于视频的反向构建来生成镜头级电影化方案，并采用语义一致性 GRPO（Semantic-Consistency GRPO，SC-GRPO）以在跨镜头与跨时间维度上忠实保留用户需求。为评估该能力，我们构建了 WanPEval——一个人工标注的测试基准，覆盖 5 至 30 秒的时长与不同意图粒度，并配有约 1.1 万次盲测成对评估。在为 Wan3.0 的视频生成器提供支持时，WanPE-397B 相较原始用户提示词在 5–15 秒区间将人类偏好提升 10.66–18.84 分，在 30 秒赛道中更是大幅提升 50.86 分。消融实验表明，反向构建明显优于前向改写，而 SC-GRPO 在不同模型规模下均能稳健保持语义保真度。最终，WanPE 在 5–15 秒区间领先所有受评估的商业产品，并在 30 秒区间与 Seedance 2.5 保持竞争力。

## IntBMoE: Integrating Block-Level Conditioning into Expert Composition for Full-Participation Mixture-of-Experts

[IntBMoE：将块级条件引入专家组合，实现全参与式混合专家模型](https://arxiv.org/abs/2609.21346)

混合专家（MoE）能够扩展模型容量，但现有设计无法独立设定三个量。对单个 Token 而言，参与度（participation）指有多少专家为其输出贡献知识，执行量（execution）指实际参与计算的专家数（计算成本），物化量（materialization）指需要构建并存储的专家规模参数集数量（内存成本）。稀疏路由能压低执行量与物化量，却牺牲了参与度：每个 Token 只有少数专家贡献。稠密输出混合可恢复全参与，但其执行量随专家数量增长。参数合并把执行量固定为一个专家，但其物化量随路由决策数量增长。为此我们提出 IntBMoE，一种块条件化（block-conditioned）MoE，通过将稠密专家组合与稀疏块执行相配对，实现三者的解耦。其块来自一个小型可学习码本，每个条目对应一个块。在每个内部层中，一个轻量级超网络将本层专家池中的所有专家基合并为一个组合专家。参与度是全量的，因为每个组合专家都调用了整个专家池；执行保持稀疏，因为路由器只把每个 Token 送往少数几个块；物化量有界，因为决定块数量的是码本而非输入。双路径残差门控（Dual-Path Residual Gating, DPRG）进一步通过乘性门控将两条独立组合的路径耦合起来。图像分类实验表明，该方法相较代表性的稀疏与稠密 MoE 基线均取得稳定提升；在语言建模与序列推荐上的额外实验验证了其超越视觉领域的泛化能力。IntBMoE 已完整部署于高德（AMap）的生成式推荐系统中，在 60ms 延迟预算下服务数亿用户，在线 A/B 测试中取得 2.4% 的相对 UVCTR 提升。代码已开源于 https://github.com/AMAP-ML/DreamX-Rec/ 。
